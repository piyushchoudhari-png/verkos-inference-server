# Inference API — Architecture

This document is the source of truth for the production inference API server.
Read it before touching anything under `src/serving/`, the model manager,
sglang subprocess lifecycle, or the HTTP contract.

## Context

The repo today is a thin OpenAI-compatible HTTP gateway in front of one or
more `sglang` model workers. There is no bench harness, no Streamlit UI — the
HTTP API is the only product surface. Clients are other services and humans on
the LAN ("local internet"); they call us via plain HTTP (`curl`, the OpenAI
SDK, OpenWebUI, LangChain, …). There is no Verkos SDK; the public contract is
the HTTP API itself, so it must be familiar and stable.

**Serving runtime: sglang, spawned on demand by the gateway.** sglang natively
exposes OpenAI-compatible endpoints, continuous batching, streaming,
cancellation, and KV-cache management. We do **not** write our own engine or
adapter layer.

**v1 slot model: single slot, on-demand load, implicit swap.** At most one
sglang process is alive at a time. The gateway owns that process: it spawns
sglang on the first inference request for a given model, keeps it hot
indefinitely, hard-kills it when a client explicitly calls `/unload`, and
swaps to a different model when an inference request arrives for one. This
suits our product shape — chat/VLM and embed/OCR are mutually-exclusive
features in v1 — and avoids reserving VRAM for models nobody is actively
calling. Multi-slot residency with a VRAM budget and a priority algorithm is
deferred to v2.

**Confirmed design choices:**
- API shape: **exact OpenAI / OpenRouter compatibility** — sglang gives us
  this for free at the worker layer; the gateway preserves it.
- v1 model types: **chat / VLM** + **embeddings**. OCR and legacy
  `/v1/completions` deferred — but the catalog must not block them.
- Topology: **gateway-supervised, single-slot sglang subprocess**. The gateway
  is the only long-lived process; sglang lives as its child.
- v1 reliability: **bearer API keys** (gateway-enforced, generated by a
  standalone Python script) + **health / readiness / metrics** endpoints.
  Rate limiting deferred to v2.

## Model Lifecycle & Slot Semantics

This is the v1 behavior contract that the rest of the design hangs off of.

- **Single slot.** At most one sglang process is alive in v1. The catalog of
  *available* models is declared in `gateway.yaml::models[]`; the *currently
  loaded* one is exposed via `GET /v1/models` (per-entry `state` field) and
  `GET /readyz`.
- **Implicit load on first inference.** If no model is loaded and a request
  hits `/v1/chat/completions` or `/v1/embeddings` with `"model": "X"`, the
  gateway spawns sglang for X, polls `/health` until it's ready, then forwards
  the request. The first request pays the cold-start cost; subsequent
  requests for X are hot-path.
- **Implicit swap.** If model A is currently loaded and a request arrives for
  B (with B in the catalog), the gateway hard-kills A's sglang process,
  spawns B, and forwards the request. **Any client streaming from A at that
  moment has its stream terminated.** This is the v1 contract; clients that
  share a gateway are expected to coordinate, or to use only one model. See
  also "Deferred to v2 — Drain-on-implicit-swap".
- **Explicit `POST /v1/models/{id}/load`** spawns the model without sending
  an inference request. Useful for warming a model before a known burst.
  Idempotent: a no-op when the requested model is already loaded; triggers a
  swap when a different one is loaded.
- **Explicit `POST /v1/models/{id}/unload`** hard-kills (`SIGKILL`,
  `process.wait()`) the loaded sglang process. Returns 200 in all cases (the
  model was loaded → killed; the model was not loaded → no-op).
- **Stay-hot semantics.** Loaded models stay loaded indefinitely. There is no
  idle timeout and no auto-eviction in v1.
- **Catalog gating.** Inference for a `model` id that is **not** in the
  catalog returns 404 `model_not_found`. Inference for a catalog model
  that has failed to load (last spawn errored) returns 502 `worker_error`
  with the last spawn error in the message.

## High-Level Architecture

```
                              ┌──────────────────────────────────────────┐
   curl / OpenAI SDK ───────► │  Gateway (FastAPI, 0.0.0.0:8000)         │
   OpenWebUI / LangChain      │  - Bearer auth (keys.json)               │
                              │  - Owns ONE sglang subprocess at a time  │
                              │  - Implicit load + swap on inference     │
                              │  - Explicit /load and /unload            │
                              │  - SSE pass-through                      │
                              │  - /metrics, /healthz, /readyz           │
                              └──────────────────────┬───────────────────┘
                                                     │ spawn / SIGKILL
                                                     ▼
                                ┌────────────────────────────────────────┐
                                │  sglang subprocess (currently loaded)  │
                                │  127.0.0.1:<port for this model>       │
                                │  continuous batching + KV cache        │
                                └────────────────────────────────────────┘

   Catalog (gateway.yaml::models[]):       Slot state at any moment:
     chat-vlm   → port 30001                 EMPTY
     bge-embed  → port 30002                 LOADING(<id>)
     ocr-paddle → port 30003   (v1.x)        READY(<id>)
                                             UNLOADING(<id>)
```

**Why this topology:**
- The gateway is the only ingress, the only auth check, and the only thing
  watching the GPU. sglang has no auth and binds to `127.0.0.1`.
- One model in VRAM at a time means trivial memory accounting: each catalog
  entry sizes `mem_fraction_static` against the *full* GPU, not a share. The
  loaded model gets the whole card.
- We write one FastAPI app (the gateway) and run stock `sglang.launch_server`
  as our subprocess. No custom engine code.
- Continuous batching and KV caching come from sglang.
- Failure isolation isn't a concern in single-slot v1: if the loaded model
  crashes, only that model is affected, and the manager surfaces it as 502
  on the next inference request.

The cost: any time a client asks for a model that isn't currently loaded,
they pay cold-start (typically 5–60 s depending on model size). We chose this
over always-on multi-process because v1's model classes are mutually
exclusive in our product (chat is one feature; embed+OCR is another), so
simultaneous residency wins nothing and burns VRAM.

## Part A — HTTP API Contract (gateway-facing)

### A.1 Design Principles
- OpenAI / OpenRouter compatible: drop-in `base_url` swap should "just work".
- No SDK; the HTTP contract is the product. URLs, headers, JSON shapes are stable.
- Streaming via SSE (`text/event-stream`) — sglang produces standard OpenAI
  chunk format; the gateway streams it through unchanged.
- Predictable error envelope (`{"error": {"message", "type", "code"}}` like OpenAI).
- All clients identified by Bearer key; all responses log a `request_id`.

### A.2 Endpoints (v1)

| Method | Path | Purpose |
|---|---|---|
| GET  | `/v1/models` | Full catalog, each entry tagged with `state: empty\|loading\|ready` and the capability block from its YAML. Exactly one entry will be `ready` (or none, if nothing is loaded). |
| GET  | `/v1/models/{id}` | Detail for one catalog entry, including current `state`. 404 if `id` is not in the catalog. |
| POST | `/v1/models/{id}/load` | Explicitly spawn this model. Implicit swap if a different model is currently loaded. Returns 200 once `state == ready`. Idempotent. |
| POST | `/v1/models/{id}/unload` | Hard-kill (`SIGKILL`) the loaded model if it matches `id`. Returns 200. No-op if nothing is loaded or a different model is loaded. |
| POST | `/v1/chat/completions` | Chat — text and vision. Streams via SSE. Triggers implicit load/swap. |
| POST | `/v1/embeddings` | Text embeddings — batch input, returns dense vectors. Triggers implicit load/swap. |
| GET  | `/healthz` | Liveness — gateway up |
| GET  | `/readyz` | Readiness — slot is `READY(<id>)` |
| GET  | `/metrics` | Prometheus exposition |

Reserved for later (the gateway forwards to the loaded model if it advertises
the capability, returns 404 otherwise): `/v1/ocr`, `/v1/completions`, `/v1/rerank`.

### A.3 Request / Response Shapes

The gateway honors the **exact** OpenAI-compatible JSON schemas. Since sglang
already speaks this, the gateway's job for `/v1/chat/completions` and
`/v1/embeddings` is auth + load/swap + streaming pass-through; it does not
rewrite request or response bodies.

- **Chat completions** — `model`, `messages` (system/user/assistant with
  text-or-multimodal content parts including `image_url` with data URIs or
  http URLs), `temperature`, `top_p`, `max_tokens`/`max_completion_tokens`,
  `stop`, `seed`, `stream`, `stream_options.include_usage`, `n`,
  `response_format`, `user`. Response includes `id`, `object`, `created`,
  `model`, `choices[].message`/`delta`, `usage`. Anything sglang accepts, we
  pass through.
- **Embeddings** — `model`, `input` (string or array), `encoding_format`
  (`"float"` default, `"base64"` supported), `dimensions` (model-dependent),
  `user`. Response is standard `{data: [{embedding, index}], model, usage}`.
- **/v1/models** — Returns the full catalog (not just the loaded model), with
  each entry's `capabilities` block and a `state` field. Example:

  ```json
  {
    "object": "list",
    "data": [
      {"id": "chat-vlm",  "object": "model", "state": "ready",   "capabilities": {...}},
      {"id": "bge-embed", "object": "model", "state": "empty",   "capabilities": {...}}
    ]
  }
  ```

### A.4 Streaming
- `text/event-stream` chunks (`data: {json}\n\n` ending in `data: [DONE]\n\n`).
- sglang generates the chunks; the gateway uses `httpx`'s streaming response
  to relay them byte-for-byte.
- Client disconnect → gateway aborts the upstream request → sglang cancels
  generation (sglang has native client-disconnect handling).
- **Implicit-swap interruption.** If another client's inference request
  triggers a swap while a stream is in flight, the upstream sglang process is
  hard-killed and the in-flight stream's TCP connection closes. Clients
  should treat unexpected stream termination as retryable.

### A.5 Authentication
- `Authorization: Bearer <key>` on every `/v1/*` call. Enforced by the
  gateway; **sglang does not check auth** — it's a child process bound to
  loopback.
- Keys are stored in `keys.json` (gitignored), generated by
  `scripts/generate_api_key.py` (see §C). The gateway loads this file at
  startup and on SIGHUP.
- `/healthz`, `/readyz`, `/metrics` do not require auth (so probes work).
- 401 returns OpenAI-shaped error envelope.

### A.6 Errors
- Always JSON, always shape `{"error": {"message": str, "type": str, "code": str|null, "param": str|null}}`.
- HTTP status codes:
  - 400 invalid_request_error
  - 401 authentication_error
  - 404 model_not_found (id is not in the catalog)
  - 413 request_too_large
  - 422 unprocessable_entity
  - 500 internal_error
  - 502 worker_error (sglang spawn failed, crashed, or returned 5xx)
  - 503 service_unavailable (slot is mid-transition and load timeout hasn't expired)
  - 504 timeout (cold-start exceeded `manager.load_timeout_s`)
  - 507 insufficient_storage (sglang exited with OOM during spawn) — *aspirational; the current implementation surfaces OOM as 502 until we parse sglang's stderr for OOM signatures.*
- Every error response carries `x-request-id` header.
- Errors from sglang are wrapped to ensure the envelope matches our shape.

### A.7 Gateway Routing
- On startup: parse `gateway.yaml::models[]`, build an in-memory catalog
  `{id → {port, sglang_args, capabilities}}`. The slot starts EMPTY; no
  sglang process is spawned.
- Per inference request: look up `model` in the catalog. If absent → 404. If
  present, call `manager.ensure_loaded(id)` — this returns the
  `(host, port)` of the running sglang process for `id`, spawning and/or
  swapping as needed. Forward via httpx streaming pass-through.
- Per `POST /v1/models/{id}/load`: same `manager.ensure_loaded(id)`; return
  200 with the resolved port.
- Per `POST /v1/models/{id}/unload`: `manager.unload_if(id)` — SIGKILL only
  if `id` matches the loaded model; otherwise no-op. Return 200.
- State transitions guarded by a single `asyncio.Lock` so concurrent
  inference requests never race a swap. Concurrent requests for the *same*
  model coalesce on the same load.
- Gateway adds `x-request-id`, propagates an auth-derived client identifier
  as an internal header (`x-verkos-client`) so per-key usage can be logged.

### A.8 Observability
- Structured JSON logs via `python-json-logger`: one log line per request
  with `request_id`, `model`, `route`, `status`, `latency_ms`,
  `prompt_tokens`, `completion_tokens`, `client_key_name`. Lifecycle events
  (`load_started`, `load_complete`, `load_failed`, `unload_started`,
  `unload_complete`) carry `model`, `pid`, `duration_ms`, `error`. An implicit
  swap is logged as `unload_started`/`unload_complete` for the outgoing model
  followed by `load_started`/`load_complete` for the incoming one.
- `/metrics` (Prometheus) aggregates:
  - `verkos_requests_total{route,model,status}` counter
  - `verkos_request_duration_seconds{route,model}` histogram
  - `verkos_tokens_total{model,kind=prompt|completion}` counter
  - `verkos_inflight_requests{route,model}` gauge
  - `verkos_model_state{model,state=empty|loading|ready}` gauge (1.0 for current)
  - `verkos_model_loads_total{model,result=ok|error}` counter
  - `verkos_model_load_duration_seconds{model}` histogram
  - `verkos_gpu_memory_used_bytes{gpu}`, `verkos_gpu_memory_total_bytes{gpu}`,
    `verkos_gpu_utilization_ratio{gpu}` (NVML via `src/gpu_poller.py`)
- `/healthz` always 200 if process is alive.
- `/readyz` returns 200 only when the slot is `READY(<id>)`. EMPTY/LOADING/
  UNLOADING return 503 with the current state in the body.

### A.9 Deployment
- **One systemd unit only:** `verkos-gateway.service`. sglang is spawned as
  the gateway's child process, not as a separate unit.
- Gateway binds to `0.0.0.0:8000` for LAN access. sglang binds to
  `127.0.0.1:<port from catalog>`.
- On gateway SIGTERM: the manager kills the current sglang child (if any),
  awaits the child, then the gateway exits.
- Single GPU box: only one model is loaded at a time, so each catalog entry
  can size `mem_fraction_static` against full VRAM.
- Multi-GPU sharding via per-model `CUDA_VISIBLE_DEVICES` is supported via
  catalog env-var passthrough (deferred — we just haven't exercised it).

## Part B — Model Serving via sglang

### B.1 Why sglang (and what we no longer have to build)
- Native OpenAI-compatible endpoints (`/v1/chat/completions`, `/v1/embeddings`,
  `/v1/models`, `/health`).
- Continuous batching across in-flight requests.
- RadixAttention KV-cache reuse (big win for repeated system prompts).
- Streaming + client-disconnect cancellation are native.
- Multi-modal (VLM) support for the major model families.
- Embedding mode (`--is-embedding`) for embedding models.

### B.2 sglang Process — Spawned On Demand by the Gateway
The gateway spawns sglang via `asyncio.create_subprocess_exec`, not systemd.
Example resolved argv for the chat/VLM model:

```bash
python -m sglang.launch_server \
  --model-path /models/chat-vlm \
  --host 127.0.0.1 \
  --port 30001 \
  --served-model-name chat-vlm \
  --mem-fraction-static 0.85 \
  --dtype bfloat16 \
  --chat-template chatml
```

For an embedding worker, add `--is-embedding` and drop the chat-template
flag. Any other `sglang.launch_server` flag is fair game — the gateway
passes them through verbatim from the per-model YAML.

The translation logic (YAML → argv) lives in `src/serving/launcher.py` and is
consumed by both `src/serving/manager.py` (production) and
`scripts/launch_worker.py`. The latter is a **debug-only helper** that runs
the translation against a single YAML so an operator can boot sglang
standalone (without the gateway) to verify weights load. It is not the
production path.

### B.3 Per-Model Catalog Entry (`workers/<name>.yaml`)

```yaml
worker:
  # The id clients send in the OpenAI `model` field. Also doubles as the
  # catalog key. Kept under `worker.*` for backwards compatibility with the
  # debug helper that still parses this schema.
  name: "chat-vlm"
  host: "127.0.0.1"          # always 127.0.0.1; the gateway is the only ingress
  port: 30001                # pre-assigned per model; the gateway uses this
sglang:
  model_path: "/models/chat-vlm"
  served_model_name: "chat-vlm"
  dtype: "bfloat16"
  mem_fraction_static: 0.85
  chat_template: "chatml"
  is_embedding: false
  # Any other sglang.launch_server flag can be added here and is passed through.
capabilities:
  chat: true
  vision: true
  embeddings: false
  max_context_tokens: 32768
  max_image_pixels: 2_000_000
```

### B.4 Gateway Config (`gateway.yaml`)

```yaml
auth:
  keys_file: "/etc/verkos/keys.json"   # generated by scripts/generate_api_key.py
models:
  - id: "chat-vlm"
    config_ref: "workers/chat-vlm.yaml"   # capability + sglang + port read from here
  - id: "bge-embed"
    config_ref: "workers/bge-embed.yaml"
server:
  host: "0.0.0.0"
  port: 8000
  log_level: "info"
gpu:
  poll_interval_s: 5.0
manager:
  load_timeout_s: 120.0            # max wait for /health to flip after spawn
  health_poll_interval_s: 0.5
  spawn_python: null               # null → use the gateway's interpreter
```

`config_ref` paths are resolved relative to `gateway.yaml`'s directory unless
absolute. Inlining the `sglang` and `capabilities` blocks directly under
`models[]` is also accepted for compactness.

### B.5 Slot Lifecycle (`manager.py`)
States: `EMPTY`, `LOADING(id)`, `READY(id)`, `UNLOADING(id)`. Guarded by one
`asyncio.Lock`.

Transitions:

- **EMPTY → LOADING(X) → READY(X):** triggered by `ensure_loaded(X)` or
  `POST /v1/models/X/load`. Spawn `sglang.launch_server` for X; poll
  `http://127.0.0.1:<X.port>/health` every `health_poll_interval_s` until 200
  or `load_timeout_s` expires.
- **LOADING(X) → EMPTY:** spawn exited non-zero, timeout exceeded, or
  process was lost. Last error is stashed for the next caller and exposed
  in logs / `verkos_model_loads_total{result="error"}`.
- **READY(X) → UNLOADING(X) → EMPTY:** triggered by
  `POST /v1/models/X/unload` or by `ensure_loaded(Y)` (implicit swap).
  `process.kill()` then `await process.wait()`. No drain.
- **READY(X) + ensure_loaded(Y):** READY(X) → UNLOADING(X) → EMPTY →
  LOADING(Y) → READY(Y). Whole transition happens under the lock;
  concurrent inference requests block and serialize behind it.
- **READY(X) + ensure_loaded(X):** fast path — return `(host, port)`
  immediately, no transition.

Caller semantics:
- `ensure_loaded(id) -> (host, port)`: blocks across swaps. Raises `KeyError`
  if `id` is not in the catalog (`app.py` maps this to 404 `model_not_found`).
  Raises `SpawnFailedError` if spawn fails (mapped to 502 `worker_error`).
  Raises `LoadTimeoutError` if `load_timeout_s` expires (mapped to 504
  `timeout`).
- `unload_if(id) -> bool`: returns True if a process was killed, False if
  the slot was already EMPTY or held a different model.
- `current() -> SlotSnapshot`: returns a snapshot of `(state, id, port, pid,
  last_error)` for read-only introspection (used by `/v1/models`, `/readyz`,
  and metrics).
- `shutdown()`: invoked from the FastAPI lifespan teardown — kills any live
  child and awaits its exit so SIGTERM leaves no orphans.

### B.6 GPU Memory
- Each catalog entry's `mem_fraction_static` is sized against **full** VRAM,
  not a share — only one model is loaded at a time, so they don't compete.
- If sglang exits with OOM during spawn, the manager surfaces 507
  `insufficient_storage` and the slot stays EMPTY. The operator tunes the
  catalog and retries.
- pynvml gauges via `src/gpu_poller.py` continue to expose
  `gpu_memory_used_bytes` and friends, regardless of slot state.

## Part C — API Key Generation

Internal API → no DB, no admin UI. Keys are produced by a standalone Python
script and stored in a JSON file the gateway reads.

### C.1 Script: `scripts/generate_api_key.py`

Standalone CLI. Generates a cryptographically random key, writes a record to
`keys.json`, prints the key to stdout **exactly once** so the operator can
copy it to the client.

Usage:

```bash
# Generate a key for "data-team", append to default keys file (./keys.json)
python scripts/generate_api_key.py --name data-team

# Specify the keys file path
python scripts/generate_api_key.py --name alice --keys-file /etc/verkos/keys.json

# List existing keys (names + created_at + prefix only; full key never printed again)
python scripts/generate_api_key.py --list

# Revoke a key by name
python scripts/generate_api_key.py --revoke data-team
```

Behavior:
- Key format: `sk-flytbase-airr-<43 url-safe chars>` (i.e. `secrets.token_urlsafe(32)`).
- Refuses to overwrite an existing name (names are append-only for audit
  integrity); use `--revoke` to invalidate, then mint a new name.
- `keys.json` is created with mode `0600` if it doesn't exist.
- Each record: `{"name": str, "key": str, "created_at": ISO8601,
  "revoked_at": ISO8601 | null}`.
- Listing prints `name | created_at | revoked_at | key_prefix (first 12 chars)` —
  never the full key.
- No external dependencies beyond Python stdlib.

### C.2 `keys.json` Shape

```json
[
  {
    "name": "data-team",
    "key": "sk-flytbase-airr-AbCdEfGh...",
    "created_at": "2026-05-22T10:15:00Z",
    "revoked_at": null
  }
]
```

### C.3 Gateway Behavior with `keys.json`
- Loaded at startup; each non-revoked key is added to an in-memory snapshot
  with a `key → name` map for logging.
- SIGHUP reloads the file (so revoking a key takes effect without restart).
- Missing file → gateway refuses to start with a clear error.
- A request with `Authorization: Bearer <unknown-or-revoked>` → 401 with
  OpenAI-shaped error envelope.

### C.4 Operational Notes
- `keys.json` is gitignored. Document this in README and in the script's
  help output.
- Recommend keeping it in `/etc/verkos/` with the gateway process user as
  the only reader.
- Revoking does not delete; it sets `revoked_at` so audits remain intact.

## Deferred to v2

- **Drain-on-implicit-swap.** v1 hard-kills in-flight requests when a swap is
  triggered by another client's inference. v2 should wait for in-flight
  requests on the outgoing model to drain (with a per-route timeout) before
  swapping. Explicit `POST /v1/models/{id}/unload` continues to hard-kill —
  it's an operator/admin action, not multi-tenant.
- **Multi-slot with VRAM budget.** v1 holds one model at a time. v2 lets the
  operator declare a VRAM budget and the manager loads as many as fit,
  evicting LRU (or by priority — see next) when a load would exceed budget.
- **Priority algorithm.** Per-model priority so high-priority requests can
  preempt lower-priority models. E.g., chat-VLM (priority 1) can evict
  embed+OCR (priority 2). Maps onto the user's "VLM is one feature,
  embed+OCR is another" framing.
- Rate limiting & per-key quotas.
- OCR endpoint (`/v1/ocr`) + dedicated OCR model entry.
- Legacy `/v1/completions`.
- Tool / function calling.
- JSON-mode / structured outputs.
- Reranking (`/v1/rerank`).
- Multi-GPU sharding via per-model `CUDA_VISIBLE_DEVICES`.
