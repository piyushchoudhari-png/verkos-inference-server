# Verkos Inference Server

OpenAI-compatible HTTP inference gateway in front of a single
[`sglang`](https://github.com/sgl-project/sglang) subprocess. Hosts local
VLMs, LLMs and embedding models on the LAN with a single bearer-key surface so
any OpenAI-compatible client (curl, the OpenAI SDK, OpenWebUI, LangChain, …)
can drop in by swapping `base_url`.

The full design is in [`docs/INFERENCE_API_ARCHITECTURE.md`](docs/INFERENCE_API_ARCHITECTURE.md).
**Read it before touching anything under `src/serving/` or the HTTP contract** —
it is the source of truth.

## Topology

```
client ──► gateway (FastAPI, :8000) ──spawn/SIGKILL──► sglang subprocess
                                                       (127.0.0.1:<port for this model>)
```

- The gateway is the only ingress and the only place auth is enforced.
- **Single slot**: at most one sglang process is alive at a time.
- **Implicit load + swap**: the first inference for a catalog model spawns
  sglang; an inference for a different catalog model hard-kills the loaded
  process and spawns the new one. v1 contract — in-flight streams to the
  outgoing model are dropped.
- Stock `sglang.launch_server` is the subprocess; no custom Python in the hot path.

```
  generate_api_key.py                # stdlib-only API key CLI

  chat-vlm.yaml                      # chat/VLM catalog entry (sglang flags + capabilities + loopback port)
  bge-embed.yaml                     # embeddings catalog entry

  gpu_poller.py                      # NVML helpers, reused by gateway metrics
  serving/                           # gateway (FastAPI) + single-slot ModelManager

deploy/
  systemd/verkos-gateway.service     # single systemd unit (sglang is the gateway's child)
  prometheus/verkos.yaml             # scrape_configs snippet
```

## Operator workflow

```bash
# 1. Mint an API key for a client.
uv run python scripts/generate_api_key.py --name data-team

# 2. (Optional) Boot sglang standalone to verify weights load — debug only.
uv run python -m scripts.launch_worker --config workers/chat-vlm.yaml --dry-run
uv run python -m scripts.launch_worker --config workers/chat-vlm.yaml

# 3. Run the gateway. The first inference request spawns sglang on demand.
cp gateway.yaml.example gateway.yaml   # then edit
uv run python -m src.serving --config gateway.yaml

# 4. Explicit lifecycle endpoints (optional — inference triggers these implicitly).
curl -XPOST -H "Authorization: Bearer $KEY" http://localhost:8000/v1/models/chat-vlm/load
curl -XPOST -H "Authorization: Bearer $KEY" http://localhost:8000/v1/models/chat-vlm/unload
```

## Endpoints

| Method | Path | Auth | Purpose |
|---|---|---|---|
| GET  | `/healthz`               | no  | Liveness — process is up |
| GET  | `/readyz`                | no  | Slot is `READY(<model>)` |
| GET  | `/metrics`               | no  | Prometheus exposition |
| GET  | `/v1/models`             | yes | Full catalog with per-entry `state` |
| GET  | `/v1/models/{id}`        | yes | One catalog entry |
| POST | `/v1/models/{id}/load`   | yes | Spawn / swap to this model (idempotent) |
| POST | `/v1/models/{id}/unload` | yes | SIGKILL if loaded; no-op otherwise |
| POST | `/v1/chat/completions`   | yes | Triggers implicit load/swap, streams via SSE |
| POST | `/v1/embeddings`         | yes | Triggers implicit load/swap |

See [`docs/INFERENCE_API_ARCHITECTURE.md`](docs/INFERENCE_API_ARCHITECTURE.md) §A for the full contract.

## Deployment

Run the gateway as a single systemd unit. sglang is its child process — there
is no separate worker unit.

```bash
# Prereqs: a `verkos` user; /etc/verkos/{gateway.yaml,keys.json}; /opt/verkos checkout with `uv sync`.
sudo install -d -o verkos -g verkos -m 0750 /etc/verkos /var/log/verkos
sudo cp gateway.yaml.example /etc/verkos/gateway.yaml   # then edit
sudo -u verkos uv run python scripts/generate_api_key.py --name initial --keys-file /etc/verkos/keys.json

sudo cp deploy/systemd/verkos-gateway.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now verkos-gateway

# Reload keys without restart:
sudo systemctl reload verkos-gateway
```

For Prometheus, merge [`deploy/prometheus/verkos.yaml`](deploy/prometheus/verkos.yaml)
into your scrape configs. The file lists every metric the gateway exposes plus
recommended dashboard panels (slot state, cold-start latency, GPU headroom).

## API tests

Curl-driven end-to-end suite at `tests/api/run.sh`. Point it at a running
gateway with a valid bearer key:

```bash
GATEWAY_URL=http://localhost:8000 \
API_KEY=sk-flytbase-airr-...        \
./tests/api/run.sh

# No-load smoke (health, auth, catalog shape, error envelopes):
SKIP_INFERENCE=1 GATEWAY_URL=... API_KEY=... ./tests/api/run.sh
```

Requires `curl` + `jq`. Override `CHAT_MODEL` / `EMBED_MODEL` if your catalog
uses different ids, and `COLD_START_TIMEOUT` (default 180s) to widen the
per-cold-start budget.
